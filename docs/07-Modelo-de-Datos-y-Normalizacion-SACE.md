## 7. Modelo de datos y normalización — SACE (AleLeo Tours)
### 7.1 Propósito
Documentar el modelo de datos implementado en la base de datos SACE_db del sistema SACE: tablas, claves e integridad referencial, restricciones, nivel de normalización alcanzado (1FN, 2FN y 3FN) y la correspondencia entre el esquema y los requerimientos funcionales. El esquema físico completo se entrega en docs/SACE_db_ddl.sql (generado con pg_dump --schema-only, sin datos); las tablas se crean automáticamente con ddl-auto=update y los datos iniciales los siembra DataInitializer.

### 7.2 Modelo de datos implementado
El esquema tiene 11 tablas en el esquema public de PostgreSQL 18.4:

| Tabla | Propósito | Clave primaria |
|---|---|---|
| persona | Entidad base con herencia (tipo_persona_discriminador): datos comunes de clientes y empleados (nombre, apellido, email, contraseña cifrada, documento, teléfono, tipo de usuario, estado de acceso). | id (identity) |
| cliente | Especialización de persona para clientes (historial de consultas y preferencias de comunicación). | id (PK + FK a persona) |
| empleado | Especialización de persona para empleados (cargo específico, departamento y disponibilidad). | id (PK + FK a persona) |
| solicitud | Solicitudes de soporte por categoría (RESERVA, CONSULTA, CAMBIO_FECHA, EQUIPAJE, OTRO), estado y prioridad. | id (identity) |
| mensaje | Mensajes del hilo de conversación por solicitud (TEXTO, ARCHIVO o SISTEMA) con ruta del adjunto y calificación. | id (identity) |
| pago | Pagos: monto, método, llave de destino, estado, fecha, URL del comprobante y notificación. | id_pago (identity) |
| servicio | Catálogo de servicios/destinos con precio decimal preciso y tipo de servicio. | id (identity) |
| pregunta_frecuente | Catálogo del chatbot: pregunta, respuesta, categoría y palabras clave. | id (identity) |
| chatbot | Instancia del bot con nombre, versión y estado operativo. | id (identity) |
| cliente_servicio | Relación muchos a muchos entre clientes y servicios (destinos del cliente). | Clave compuesta (cliente_id, servicio_id) |
| chatbot_pregunta_frecuente | Relación muchos a muchos entre chatbot y preguntas frecuentes. | Clave compuesta (chatbot_id, pregunta_frecuente_id) |

### 7.3 Relaciones e integridad referencial
Las relaciones se garantizan mediante claves foráneas y claves primarias declaradas en la base de datos:

| Relación (FK) | Origen → Destino | Regla |
|---|---|---|
| cliente.id → persona.id; empleado.id → persona.id | especializaciones de persona | Cada cliente/empleado pertenece a una persona (herencia por tabla) |
| solicitud.cliente_id → cliente.id | Solicitud del cliente | Una solicitud pertenece a un único cliente |
| solicitud.empleado_asignado_id → empleado.id | Asignación del asesor | Una solicitud puede asignarse a un empleado de soporte |
| solicitud.chatbot_asignado_id → chatbot.id | Primera atención del bot | Una solicitud puede asignarse al chatbot |
| solicitud.servicio_generado_id → servicio.id | Servicio generado | El asesor puede generar un servicio para la solicitud |
| mensaje.solicitud_id → solicitud.id | Mensajes por hilo | Cada mensaje pertenece a una solicitud |
| pago.id_cliente → cliente.id | Pagador | Cada pago corresponde a un cliente |
| pago.id_solicitud → solicitud.id | Solicitud pagada | Cada pago corresponde a una solicitud (anti-doble-cobro) |
| cliente_servicio.(cliente_id, servicio_id) → cliente.id, servicio.id | Destinos del cliente (M:N) | Tabla puente normalizada |
| chatbot_pregunta_frecuente.(chatbot_id, pregunta_frecuente_id) → chatbot.id, pregunta_frecuente.id | FAQs del bot (M:N) | Tabla puente normalizada |

### 7.4 Restricciones e integridad
- Claves primarias con GENERATED BY DEFAULT AS IDENTITY (secuencias propias por tabla).
- Restricciones CHECK para valores controlados: estados de solicitud (PENDIENTE, EN_PROCESO, RESUELTA, CANCELADA), prioridad (BAJA, MEDIA, ALTA, URGENTE), tipo de usuario, estado de acceso, tipo de documento, disponibilidad del empleado, tipo de mensaje y tipo de servicio.
- Campos obligatorios declarados NOT NULL en datos críticos (p. ej. pago.monto, pago.llave_destino, pago.fecha_pago, pago.estado, persona.tipo_persona_discriminador).
- Tipos numéricos precisos para dinero: numeric(12,2) en pago y numeric(19,2) en servicio (sin errores de redondeo).
- Indices y secuencias generados por identidad para un acceso eficiente por clave.
### 7.5 Nivel de normalización alcanzado
| Forma normal | Verificación en el modelo |
|---|---|
| 1FN (atributos atómicos) | Cada celda contiene un único valor; no hay grupos repetidos ni arreglos; las relaciones M:N se resuelven con tablas puente (cliente_servicio, chatbot_pregunta_frecuente). |
| 2FN (dependencia total de la clave) | Todas las claves primarias son simples (o compuestas solo en las tablas puente, cuyos únicos atributos son las dos claves foráneas, sin atributos no clave). Ningún atributo depende de parte de una clave compuesta. |
| 3FN (sin dependencias transitivas) | Los datos repetibles se extraen a tablas de catálogo (servicio, pregunta_frecuente, chatbot) referenciadas por FK; ningún atributo no clave depende de otro atributo no clave. |

El modelo está normalizado hasta la 3FN: las tablas puente resuelven las M:N y los catálogos evitan redundancias y anomalías de actualización en los datos maestros.

### 7.6 Correspondencia con los requerimientos
| Requerimiento | Soporte en el modelo |
|---|---|
| RF-01 Registro de clientes | tabla persona (especializada en cliente) con email y documento únicos y contraseña cifrada |
| RF-02 Inicio de sesión y roles | persona.tipo_usuario + estados de acceso (ACTIVA/INACTIVA/BLOQUEADA) |
| RF-03 Catálogo público de destinos | tabla servicio (nombre, destino, precio, tipo) |
| RF-04/05/06 Solicitudes por categoría y propiedad | tabla solicitud con cliente_id (FK de propiedad) y categoría |
| RF-07 Chat de mensajes por solicitud | tabla mensaje con solicitud_id y tipo de mensaje |
| RF-08 Chatbot con FAQs | tablas chatbot, pregunta_frecuente y la puente chatbot_pregunta_frecuente |
| RF-09 Panel del empleado | tabla empleado (disponibilidad, departamento, cargo) |
| RF-10 CRUD de administración | tablas cliente, empleado, servicio, solicitud, pregunta_frecuente |
| RF-11/12 Pago y comprobante | tabla pago con id_solicitud (anti-doble-cobro), monto, llave y URL del PDF |
| RF-13 Reportes y KPIs | agregaciones sobre solicitud y pago (precio real de servicio) |
